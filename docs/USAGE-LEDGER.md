# 用量规模与费用结构（权威账本）

> 2026-10-12。数据源：`~/.dsh/storages/session_projcache.json` 的 token-meter 持久化投影
> （路径 `tables.sessions.<id>.rows.tokenUsage.val.totals`）。这是**权威账本**，
> 比 session 日志可靠 —— 后者只有少数 step 带 usage。

## 一、字段语义（`packages/llm/llm/src/types.ts:130`）

计数是**互斥**的，不是嵌套的：

```
inputTokens      = 未命中（全价 $1/M）的输入
cacheReadTokens  = 命中（折扣价 $0.02/M）的输入
cacheWriteTokens = 写入
计费输入 = inputTokens + cacheReadTokens
```

⚠️ 踩过的坑：`session.jsonl.zstd` 里 usage 在 **`data.usage`**（不是 `message.usage`），
且字段名是 `inputTokens` / `cacheReadTokens`（**不是** `prompt_cache_hit_tokens`）。

## 二、全机累计（101 个会话，23,541 步）

| 项 | tokens | 单价 | 费用 | 占比 |
|---|---|---|---|---|
| 命中输入 | 7,230,893,952 | $0.02/M | **$144.62** | **57.7%** |
| 未命中输入 | 42,164,513 | $1.00/M | $42.16 | 16.8% |
| 输出 | 21,284,668 | $3.00/M | $63.85 | 25.5% |
| **合计** | **7,294,343,133** | | **$250.64** | 100% |

命中率 **99.42%**。

## 三、关键洞察：命中率已经到顶，钱在"总量"

`99.42%` 看着完美，但**命中 token 有 72 亿个** —— 即使打折价，光"命中"就付了
**$144.62（占 58%）**。命中率再提高也没空间了（剩 0.58%）。

⇒ **降本杠杆只有两个：① 减少步数 ② 压小单次 payload。**

```
总输入 = 单次 payload × 步数
平均每次出网输入 308,961 tokens  ← 体感"用量大"的来源
平均每次出网输出     904 tokens
```

> 会话 ID 与工作区名已隐去 —— 它们对本结论没有意义，只会暴露作者本机环境。

**单次 payload 30~42 万 token** 是核心问题（不是命中率）。

## 五、插件的贡献定位

插件只压 reasoning（压缩率 92%，推理占出网 payload 32.7%）：

```
命中部分省 $144.62 × 30.1% ≈ $43.53
```

即插件大约承担了**总账 $250.64 里的 $43.53（约 17%）**，且**只影响命中那 58%**
（不改输出、不消除断点）。
